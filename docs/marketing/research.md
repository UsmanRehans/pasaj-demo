# Marketing Skills repository review

Reviewed September 28, 2026. Source: [coreyhaines31/marketingskills](https://github.com/coreyhaines31/marketingskills), commit `5b2c0007766c6a1cf1d53fd8fc73e979e0821022`.

## Findings

- The snapshot contains 50 skill entry points, supporting references, evaluation examples and tool integration documentation/helpers. The README groups capabilities into seven branches under shared `product-marketing` context.
- It supplies reusable workflows rather than a named employee organization. PASAJ’s existing Cando, Avery, Lauren, Vita, Nico and Theo roles provide ownership and collaboration.
- Strong reusable pieces include shared context, research before copy, channel-specific deliverables, measurement plans and related-skill handoffs.
- Several workflows explicitly target SaaS: trials, software activation, seat-based pricing, subscription churn, Product Hunt launches and B2B pipeline. Those need translation or deferral for scent, skincare and home fragrance.
- The council skill simulates famous advisors. This differs from PASAJ’s actual-agent review workflow. The loops skill describes recurring work; copying it does not activate a scheduler.
- Integration examples are not account connections. The tool registry includes disclosed sponsored partners; selection should follow PASAJ’s actual needs and stack.
- Upstream benchmarks, expected lifts and platform assertions require independent verification before use. In particular, AI search crawler distinctions need checking; offer design should not impose bonuses, urgency or discounts on PASAJ.

## What was duplicated

The unmodified `skills/` and `tools/` directories and source documentation are retained under `upstream/`, with the MIT license and original attribution. `upstream-manifest.json` pins the revision and file hashes. No source helper was executed. PASAJ’s entry point, team mapping and product context sit outside that snapshot, so adaptations remain distinguishable from the author’s work.

The review covered repository architecture and actual playbooks across the groups, with selective supporting-reference review. It is not an audit of every CLI implementation or every upstream claim. Tools remain reference material until inspected for a specific authorized task.
